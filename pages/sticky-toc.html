Type-checking in the REPL

The simplest way to interact with Lean is through its REPL. Type an expression, and Lean reports its type. #check 1 + 2 shows that the expression has type Nat.

The basic types

Lean ships with the usual primitive types: Nat, Int, String, Bool. Each is a term-level inhabitant of the type Type.

Building types from types

Function types are written with arrows: Nat → Nat. Product types are pairs: Nat × String. Sum types are tagged unions: Nat ⊕ String.

Application and currying

Function application is written by juxtaposition. f x y means (f x) y: apply f to x, then apply the result to y. All multi-argument functions are curried.

Lambdas

Anonymous functions use fun: fun x => x + 1 is a function that adds one. Lambdas with multiple parameters desugar into nested single-parameter lambdas.

Defining functions

Top-level definitions use def: def double (x : Nat) : Nat := 2 * x. The body comes after :=. Lean infers types where it can.

Types are objects

In Lean, types are themselves values. Nat has type Type; Type has type Type 1; the universe hierarchy continues upward to avoid Russell-style paradoxes.

Dependent arrows and products

Dependent function types let the return type depend on the argument: (n : Nat) → Vector α n. Dependent products generalize pairs to sigma types.
